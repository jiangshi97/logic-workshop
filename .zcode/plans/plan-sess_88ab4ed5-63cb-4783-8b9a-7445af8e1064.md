# 关卡包机制：新增关卡独立成包 + JSON→TS 扩展钩子（老关卡一字不动）

## 设计决策（对应你的要求）

1. **新关卡全部走 `content/packs/<包名>/`**：关卡 JSON 与该包专属 TS（生成器、钩子、机器、电路）同居一个文件夹；`content/levels/` 与现有 57 关原样不动。此后加关卡 = 建包目录 + `npm run regen:levels`，核心代码零修改。
2. **关卡 id 仅在本包内唯一**：包描述符声明一个固定的 `idBase`（如 100），包内每关的全局 id = `idBase + JSON id`。作者只需在包内从 1 任意编号（允许跳号），完全不用关心全局计数。编译期守卫：各包推导区间不得相交、且必须整体位于基础关卡（1..57）之上——全局 id 严格递增 == 目录顺序不变式保持，教学组件 sourceLevel 等"id 序即位置序"的旧比较天然继续成立。存档、运行时、判题全部沿用数字 id，**不改存档键格式、不重写旧关卡代码的 id 比较**（若改成 `包名:id` 字符串键，`Circuit.levelId` 等十几处旧逻辑都要跟着改类型，与"别动老关卡"冲突）。
3. **展示与进度按目录位置，不按 id 数值**（新 `src/progress.ts`）："第 N 关"、解锁、"下一关"全部按合并目录的位置计算；对现有 1..57（位置 == id）所有显示与行为逐字节不变，新关卡即使全局 id 是 101 也显示为第 58 关。
4. **JSON 用字符串键引用包内 TS 能力**（沿用 `program.machine` → machines 注册表的既定惯例：编译期只校验形状，运行期解析）：
   - `"sequential": { "generator": "包名/生成器名" }`（及 cases 生成器）
   - `"hooks": { "onEnter" / "onFirstClear" / "onFirstFail": "包名/钩子名" }` —— 你要的"第一次通关后执行特殊行为"即 onFirstClear
   - `"program": { "machine": "机器key" }`（已有字段；包可注册新机器）

## 一、LevelPack 接口与目录约定

```
content/packs/isa-extension/        ← 下一轮的真实包；本轮只落一个 example
  index.ts        export const pack: LevelPack = { ... }
  levels/*.json   关卡数据（同 LevelSpec + 新可选 hooks 字段；id 为包内编号）
  其余 TS 自由组织（生成器/钩子/机器电路/参考实现）
```

```ts
interface LevelPack {
  key: string;                                   // = 文件夹名，全局唯一
  idBase: number;                                // 包内关卡全局 id = idBase + JSON id（固定不随版本变）
  chapters?: string[];                           // 追加章节标题（编号接在基础 7 章后）
  scenarioGenerators?: Map<string, ScenarioGenerator>;
  caseGenerators?: Map<string, CaseGenerator>;
  machines?: MachineDescriptor[];                // sourceLevel 写包内编号，合并时翻译成全局 id
  hooks?: Map<string, LevelHook>;                // (ctx: HookContext) => void
}
interface HookContext { level: Level; notify(text: string): void; showMessage(title: string, body: string): void; }
```

`GeneratorContext` 增加 `pack?` / `localId?`（包生成器用包内编号思考，旧生成器无感）。

包规则（写入文档并由 example 包示范）：index.ts 顶层只组装描述符、不调用 levels/machines 的函数（模块求值期 levels 尚未就绪）；生成器/钩子不得依赖 `levels` 目录（编译期触发）；对 machines.ts 仅允许 type import（防运行时循环），机器的 circuit()/library() 在回调内调用核心助手。

## 二、生成脚本与装载链路

- `scripts/generate-level-data.mjs` 扩展（仍一次 `npm run regen:levels`）：
  - 扫 `content/levels/*.json`（不变）+ 各 `content/packs/*/levels/*.json` → `levelData`（基础在前、包按文件夹序、包内按文件名序），并输出 `levelSources`（相对路径，编译报错用）与 `levelPackTags`（'' = 基础）；
  - 扫 `content/packs/*/index.ts` → 新 `src/levelPacks.generated.ts`（`export const levelPacks: LevelPack[] = [...]`）。沿用"生成文件提交入库"的既定路线（Playwright 转译器不支持 import.meta.glob）。
- `tsconfig.json` include 增加 `content/packs`。
- `levelRegistry.ts`：导出纯函数 `compileCatalogue(data, sources, tags, packs)` —— 编译（包关卡 id 加 idBase）+ 守卫：全局 id 唯一（含与基础目录）；全部包全局 id > 基础最大 id；各包推导区间不相交；chapter ≤ 合并章节数；包 key / 机器 key 无重复。报错带源文件路径（现为"第 N 个文件"）。
- `levels.ts`：levels 聚合与按 id 排序不变；`chapters = [基础 7, ...各包 chapters]`；chapter 上界校验从 levelSpec 的硬编码 1..12 移到这里。

## 三、进度去硬编码（新 src/progress.ts，纯函数可单测）

`levelPosition(id)` / `displayNumber(id)`（=位置+1）/ `isUnlocked(id, done)` / `nextLevelId(id)` / `frontierLevelId(unlocked)`。改造点（对现有目录全部等价）：

- `App.tsx`：侧边栏锁 `item.id > unlocked`、`第 ${item.id} 关` 标签、关卡序号 pill、章末范围标签、`changeLevel` 守卫 `id > unlocked`、下一关按钮 `current + 1`、末关判定 `current === levels.length` → 全部改走 progress；chapterGroups 过滤空章节组（防 0 课章节渲染崩溃）。
- `WorkshopView.tsx` 两处 `(sourceLevel ?? 0) >= unlocked`（id 与计数混比）→ isUnlocked。
- `storage.ts`：currentLevel 校验从 `[1, unlocked]` 数值区间改为"目录内且位置 < unlocked"，回落前沿关 id（对 1..57 语义相同）。
- 教学组件 sourceLevel 门控（`>= current`）保留 id 比较：目录 id 严格递增 ⇒ id 序 == 位置序，天然正确。

## 四、编译器扩展（levelSpec.ts）

- `LevelSpec.hooks?: { onEnter?; onFirstClear?; onFirstFail? }`：键限三个事件名（未知键报错并列出合法值），值形状校验 `/^[a-z0-9][a-z0-9-]{0,63}(\/[a-z0-9][a-z0-9-]{0,63})?$/` → 条件展开到 `Level.hooks`。
- `expandWith` 命名空间解析：引用含 `/` → 在包生成器注册表中查 `包key/名字`；裸名 → 旧 `levelGenerators` 映射（老关卡引用不变，零迁移）。

## 五、运行时钩子（App.tsx）

- 挂点：`onEnter` = 首次进入该关（changeLevel 后的 effect）；`onFirstClear` = runTest 判定通过且此前 `proofs[current]` 不存在（`App.tsx:387-389` 处）；`onFirstFail` = 该关首次判题失败。三者均一次性。
- 持久化：`Workspace` 新增可选 `firedHooks?: Record<关卡id, 已触发事件名[]>`，防导入/刷新后重放。**存档版本仍 v7**：老档缺省 = 全未触发；旧版本应用读到该字段会忽略（加法兼容）。
- 钩子 API 即 HookContext（notify 复用现有 toast；showMessage 复用现有 modal 样式新增一个通用对话框状态）；未知钩子名 → toast 报错不崩溃。

## 六、机器注册表对包开放

- `machines = [computer44, ...各包 machines]`（键冲突启动期报错；包机器的 sourceLevel 由包内编号翻译为全局 id）；`canonicalMachineLibrary()` 自动并入包机器闭包 —— 存档 v7 的"规范组件代码重建"机制天然覆盖下一轮新组件，无需改 storage。
- 从 `architectureCircuits.ts` 导出包机器所需的 Builder DSL/闭包助手（老代码不动，只加 export）。

## 七、示例空包 content/packs/example/（本轮唯一落盘的包）

index.ts 声明 idBase、注册 1 个示例场景生成器 + 1 个示例钩子，**0 关卡、0 章节、0 机器** → 总关数仍 57、机器表仍 `['computer-44']`，全部现有断言不动。目的：打通 tsc / Vite / vitest / Playwright 对 content TS 的真实编译链路（否则该路径到下一轮才首次被真实执行），并作为 ISA 包的活模板。
