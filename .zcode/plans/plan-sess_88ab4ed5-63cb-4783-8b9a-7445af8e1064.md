# 可选计算机机制 + 存档格式 v7 重设计（含你的 v5 存档迁移）

按你的选择：本轮**只做机制与存档**，不新增第二台计算机/新关卡（stash 原样保留，作为下一轮 ISA+架构扩展的基础）；编程关判定按玩家当前所选机器执行。

## 一、机器注册表与可选计算机机制

**1. 机器注册表 `src/machines.ts`（新文件）**
```ts
interface MachineDescriptor {
  key: string;              // 'computer-44'
  name: string;             // 显示名：'第 44 关计算机'
  sourceLevel: number;      // 44（解锁条件：该关有 proof）
  instructions: string[];   // 该机支持的助记符（当前 10 条）
  circuit(levelId): Circuit;        // 该机在编程关的初始电路（ROM 清空）
  library(): ComponentLibrary;      // 依赖闭包
}
export const machines = [computer44];   // 注册表即扩展点：下一轮加 computer-60（13 条指令）
```
- `computer-44` 的实现即现 `programmingMachine()`（`architectureReferenceCircuit(44)` 清 ROM）；`programmingMachine.ts` 改为薄封装，`isProgrammingLevel` 从 min/max **区间**改为 **Set**（未来 56 之后穿插非编程关不再误判）。
- `machineKeyOf(circuit)`：按规范化图（忽略位置/ROM 内容，沿用现 `graph()`）识别草稿当前持有哪台机器。

**2. 汇编器按机器筛选指令（src/assembler.ts）**
- `assemble(source, machine?)` 增加可选机器参数：遇到该机 `instructions` 之外的助记符报错 `第 44 关计算机不支持指令 AND。`（带行号）；不传机器 = 全量指令表（向后兼容现有调用）。`disassemble` 同理接受机器参数。
- 调用点改造：ProgrammingPanel 实时编译、应用汇编、storage 解析时 `programSource↔words` 复验——一律传**草稿当前机器**。

**3. 工坊机器选择器（src/ProgrammingPanel.tsx + App.tsx）**
- 仿元件宽度选择器（widthPicker）的先例：面板顶部加 `<select>`，选项 = `workspace.proofs` 中已通关其 `sourceLevel` 的机器（当前只有第 44 关一台，渲染单选项即可，机制先行）。
- 切换机器 = 用新机的 `circuit(levelId)` 替换草稿，尽量保留 `programSource`（在新机指令集下重新汇编；汇编不过则保留源码文本、清空 ROM 并标记待应用）。
- **判定按所选机器**：判题本来就是对草稿电路跑门级仿真，草稿持有哪台机器就按哪台判——天然成立，无需改 judge；只需 `validateProgrammingMachine` 从"只认第 44 关一台"改为"与注册表中**任一**机器逐字节等价即可，且该机依赖闭包齐备"。

**4. 关卡数据扩展点（不改正文）**
- `levelSpec.ts` 的 `ProgramSpec` 增加可选 `machine?: string`（默认取注册表第一台），校验值必须是注册表 key——下一轮 61+ 关可直接绑定新机；现有 45–56 的 JSON 一律不动。

## 二、存档格式 v7 重设计（src/storage.ts）

**新格式（写 v7，读 1–7）**：
| 方面 | 现状（v6） | v7 新规则 |
|---|---|---|
| 版本门 | 硬编码 `[1..6]`，未知即拒 | 接受 1–7；>7 明确报"存档来自更新版本" |
| 关卡键 | v5+ 缺任一草稿→**整档拒绝**；非数字键拒绝 | **稀疏存储**：只存玩家动过的关；缺失草稿载入时按目录合成（普通关 `createCircuit`、编程关按绑定机器）。目录外/非数字键一律忽略不拒绝 |
| 组件库 | 规范 `architecture-*` 定义整包存进档（你的档里 22 条 ≈10 万字节），ISA 一变旧档即挂 | 存档**只存玩家组件**（`component-*`）；规范机库载入时由代码现建（所有注册机器闭包的并集）并覆盖合并——机库演进不再破坏旧档，篡改面归零，档小 ~100KB |
| 旧版迁移 | v1–4 超 cap 键直接拒 | v1–4 超 cap 键改为忽略；v1–6 的 `architecture-*` 库条目剥离、玩家组件保留、规范库由代码补齐 |
| 证明链 | 断链截断（保留） | 不变：按序重验，首个缺失/不过即截断；只降级进度，**永不因此整档拒绝** |
| 其他 | 4MB 上限（`storage.ts:163` 与导入预检的已有护栏，非新增） | 保留；`currentLevel` 沉降、`workshop`、`programSource↔words` 复验、原型污染防护全部保留 |

- localStorage 键 `logic-workshop.v1` **不变**（浏览器里的旧进度下次启动自动升级为 v7）。
- `serializeWorkspace` 序列化时剪枝：与"该关合成默认值"深度相等的草稿不入档（载入时合成还原，round-trip 相等）。
- 45–56 旧编程关草档是第 44 关机器图 → `machineKeyOf` 识别为 `computer-44`，逐字节校验照旧通过；旧 `programSource` 只用 10 条指令，机器筛选汇编照旧通过——**旧档数据零改写**。
