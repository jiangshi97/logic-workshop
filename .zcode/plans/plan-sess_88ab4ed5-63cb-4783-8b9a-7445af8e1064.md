# 计划：关卡编写 API（TS/JSON）+ 元件工坊

本轮覆盖两个模块。ISA 扩展与编辑体验速改不做（备忘见文末），但关卡 API 的设计保证未来 ISA 新关卡（57+）只需写一份 JSON 数据即可接入。

## 模块 A：TS/JSON 关卡编写 API

**目标**：把"新增一关"从"在阶段文件写工厂调用 + 期望闭包 + 多处按 id 分支"变成"写一份声明式数据"。TS builder 与 JSON 文件双入口共享同一 schema，编译成现有内部 `Level`，判题/仿真/UI 消费方零改动。

### A1. 表达式迷你语言 — `src/levelExpr.ts`（新文件）
- 组合关期望值写成安全整数表达式：如 `"Diff": "(A - B) mod 16"`、`"Carry": "(A + B + Cin) div 2"`。
- 文法：整数字面量（十进制/0x 十六进制）、端口标识符；算术 `+ - * div mod`、位运算 `& | ^ ~ << >>`、比较 `= != < <= > >=`（返回 0/1）、三目 `? :`、括号。
- 递归下降解析编译为 `(inputs) => number` 闭包；纯整数、无属性访问/函数调用（无注入面）。
- 语义：`div` 截断除法；`mod` 与除数同号（数学取模，`(A-B) mod 16` 直接可用）；输出按端口位宽自动 `mod 2^bits`。
- 已逐关核对：现有 1-20 关全部期望闭包均可由此表达。

### A2. LevelSpec schema + 校验 + 编译 — `src/levelSpec.ts`（新文件）
```
LevelSpec {
  id, title, caption, goal, formula, hints[3], rewardName?, chapter(显式),
  inputs/outputs: [id, bits][] 端口元组,
  allowed?: GateType[]            // 省略则按 gateUnlocks 解锁表用 id 推导
  defaultProgram?: number[],
  combinational?: { expect: 每输出一条表达式（或真值表行数据）; cases?: 公开测试集 }
  sequential?:   { scenarios: [{id, label, frames: [{inputs, cycles?, expected[] }]}] }   // 帧时间线，预填每拍期望
  program?:      { cases: ProgramCase[]; referenceSource?: string }
}
```
- `compileLevelSpec(spec): Level`：表达式→`expectedOutputs`；帧→`sequences()`（TemporalStep 预填期望）；program 用例注册进新的 `programmingCaseRegistry`，`programmingSpec.programmingCases(id)` 先查注册表再走旧 switch（未来编程关即插即用）。
- 手写校验器（不引第三方依赖，沿用项目风格）：必填、端口 id 合法不重、位宽范围、hints 恰 3 条、表达式可解析且只引用已声明端口、帧期望键与输出端口一致、程序用例地址 0-255、id 唯一；报错信息带关卡 id。
- 编译输出补 `story=goal`、派生 `expected` 保持 `Level` 接口兼容。

### A3. JSON 加载 + 迁移第 1-20 关
- JSON 关卡置于 `content/levels/NNN-名称.json`；`src/levelRegistry.ts` 用 Vite `import.meta.glob` eager 载入→编译→在 `levels.ts` 与旧 TS 关卡合并。
- **先加快照测试**固化全部 56 关期望输出（穷举输入/场景逐步），再把第 1-20 关（组合章、样板最重）迁移为 JSON，迁移后快照必须逐位一致。
- TS 入口：`defineLevel(spec)` 类型化包装同一编译器；21-56 关（有状态数学机器）保留旧 TS 工厂不动。
- 顺手清理死字段：`Level.story`、`Level.expected` 无任何消费点，改为可选并从四个工厂删除。

### A4. 作者文档
- `docs/level-authoring.md`（新）：schema 参考、表达式语言参考、各模式完整示例、工作流（写 JSON → vitest 校验 → dev 试玩）、TS 逃生门说明。
- 更新 `docs/code-guide.md` §8"新增一关"为新流程；README 补链接。

## 模块 B：元件工坊

**目标**：独立于关卡的自由搭建视图——自由加输入/输出、交互仿真、封装入库、编辑已有组件出新版本；组件库按名称分组解决"位宽版本分散、难修改"。

### B1. 存档与校验
- `Workspace` 增加 `workshop?: Circuit`（工坊草稿），存档版本 v5→v6 迁移（缺失即无草稿）；`Circuit.levelId` 以 0 作工坊哨兵值（contracts.ts 注释说明）。
- 新增 `validateWorkshopCircuit`：直接走 `validateGraph + validateLibrary`（绕过关卡端口绑定），INPUT/OUTPUT 自由添加——它们同时就是未来组件的接口声明；沿用 200 节点/400 导线上限。
- 工坊 INPUT 开关值 v1 不持久化（每次会话即全新实验）。

### B2. WorkshopView 组件 — `src/WorkshopView.tsx`（新文件）
- 独立全屏视图（复用现有 `machineVisible` 式切换模式），不与 App.tsx 的关卡画布纠缠：自有 ReactFlow 画布 + 调色板（全部门型 + CONST + DFF + RAM + ROM + INPUT/OUTPUT + 组件库/教学组件拖放）+ 选中节点属性区（CONST 值编辑、组件展开）。
- 交互仿真复用 `useSimulation` hook：组合即时求值、时钟单步/运行/清零（DFF 可试验）；工坊自有撤销栈（镜像现有 commit 模式）。
- 入口：侧栏"组件库"标签页顶部"新建元件"按钮 + 每个库条目"编辑"按钮。

### B3. 封装 / 入库 / 编辑已有组件
- 工坊内"保存为元件"复用现有两条路径：整图打包 `packageCircuit`（INPUT/OUTPUT 即接口）与框选封装 `encapsulateSelection`，引擎零改动。
- "编辑已有组件"：把 `def.graph`（内含边界 INPUT/OUTPUT 节点）载入工坊草稿 → 修改 → 同名保存 → `define()` 自动产生 vN+1（现有按名版本机制），旧实例引用旧版本不受影响。
- 加分项（时间允许）：保存成功面板列出接口兼容、可一键更新的关卡实例（批量调用现有 `replaceComponentInstance`）。

### B4. 组件库分组
- `visibleLibraryEntries` 按名称家族分组渲染：组头 = 名称 + 最新版本 + 端口摘要；组内版本倒序、标记最新；默认放置最新版。
- 不同位宽变体按命名约定归入同族展示；教学组件标签页不动。

## 测试与验证
- vitest 新增：表达式解析（运算/优先级/取模语义/非法输入报错）、编译校验各失败分支、迁移后 1-20 关期望快照一致、注册表 id 唯一、工坊校验（自由 IO 合法/上限触发）、同名保存版本递增且旧实例不动、分组函数、存档 v6 往返 + v5 旧档迁移（docs/*-demo.json 作 fixture）。
- Playwright e2e：进工坊 → 搭半加器 → 封装入库 → 分组展示 → 拖入关卡使用；编辑已有组件出新版本。
- 全量回归：`npx tsc -b`、`npm test`、`npm run build`。

## 实施顺序
1. levelExpr（+测试）→ 2. levelSpec/编译/注册表（+测试）→ 3. 快照测试 + 迁移 1-20 + 死字段清理 → 4. 作者文档 → 5. 存档 v6 + 工坊校验（+测试）→ 6. WorkshopView + App 集成 → 7. 库分组 + 编辑已有组件 → 8. e2e + 全量验证。

## 明确不做（后续阶段备忘）
- ISA 扩展：AND/XOR/MOV（opcode 10-12，旧程序兼容；ALU 硬件已就绪，主要是控制器 ALUOp 第二位与 MOV 写源）、新教学关追加 57+、旧存档编程机关卡迁移——届时新关卡直接用本轮 JSON API 编写。
- 编辑体验速改：汇编行号、常量放置时取值、开关（toggle）元件、DFF 悬停说明、元件尺寸紧凑化。
